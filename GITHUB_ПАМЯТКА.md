# Как хранить проекты на GitHub, чтобы их можно было восстановить

## Главный принцип

Для каждого важного проекта лучше иметь отдельный репозиторий GitHub.

В репозитории должны храниться:

- код;
- настройки;
- инструкции;
- шаблоны;
- файлы зависимостей;
- примеры без конфиденциальных данных.

Не стоит хранить в открытом репозитории:

- реальные ОСВ;
- готовые отчеты с финансовыми данными;
- пароли;
- токены;
- ключи API;
- персональные данные клиентов или сотрудников.

Если нужно хранить реальные рабочие данные, репозиторий должен быть приватным.

## Минимальный набор файлов в каждом проекте

В каждом проекте желательно иметь:

- `README.md` - что это за проект и как его запустить;
- `ИНСТРУКЦИЯ.md` - инструкция для себя простым языком;
- `.gitignore` - что нельзя отправлять в GitHub;
- файл зависимостей, например `requirements.txt`, `package.json` или аналог;
- папку с настройками проекта;
- пример входного файла без реальных данных.

## Рабочие ветки

Удобная схема:

- `main` - стабильная версия;
- `develop` - рабочая версия для доработок.

В текущем GitHub-репозитории проект сохранен в ветках:

- `osv-balance-main`;
- `osv-balance-develop`.

Так сделано потому, что обычная ветка `main` в репозитории `OSB_PL_BS` уже занята другим содержимым.

## Как сохранить изменения в GitHub

В этом проекте можно запустить:

```powershell
.\save_to_github.ps1 "Короткое описание изменений"
```

Например:

```powershell
.\save_to_github.ps1 "Update report instructions"
```

Скрипт:

1. проверит изменения;
2. добавит разрешенные файлы;
3. создаст коммит;
4. отправит текущую ветку в GitHub.

## Как восстановить проект на другом компьютере

1. Откройте GitHub-репозиторий:

```text
https://github.com/swet757-cpu/OSB_PL_BS
```

2. Выберите нужную ветку:

```text
osv-balance-main
```

3. Скачайте проект или клонируйте через Git:

```powershell
git clone -b osv-balance-main https://github.com/swet757-cpu/OSB_PL_BS.git
```

4. Установите зависимости:

```powershell
pip install -r requirements.txt
```

5. Положите новую ОСВ в папку `01_ОСВ_входящие`.

6. Запустите отчет:

```powershell
python .\generate_report.py
```

## Как понять, что проект сохранен

После сохранения команда:

```powershell
git status
```

должна показывать, что нет незакоммиченных изменений.

На GitHub должен появиться новый коммит в нужной ветке.
